# MobileOps — MVP Scope

**Version:** 1.0  
**Status:** Initial scope  
**Last Updated:** November 9, 2026

## 1. MVP Objective

Build a functional operations management platform that allows small mobile service businesses to manage customers, jobs, employees, and daily operations from one centralized application.

The MVP should solve core operational problems without introducing unnecessary complexity.

## 2. Included Features

### P0 — Required for MVP

| Feature | Description |
|---|---|
| User Authentication | Secure registration and login |
| Organization Management | Create and manage a business organization |
| Dashboard | Display an overview of business operations |
| Customer Management | Create, view, update, and delete customer records |
| Job Management | Create, view, update, and manage service jobs |
| Job Status Tracking | Track jobs through their lifecycle |
| Job Assignment | Assign jobs to employees |
| Scheduling | View and organize upcoming jobs |
| Multi-Tenant Isolation | Ensure businesses cannot access another organization's data |

### P1 — After Core MVP

- Employee management improvements.
- Basic operational reporting.
- Email notifications.
- Improved scheduling functionality.

These features are not prerequisites for the first functional release.

## 3. Explicitly Excluded Features

The following features are outside the initial MVP scope.

| Feature | Reason for Exclusion |
|---|---|
| AI Assistant | Not necessary to validate the core product |
| Native iOS Application | Responsive web application comes first |
| Native Android Application | Responsive web application comes first |
| Advanced Accounting | Outside initial operational scope |
| Payroll Processing | Adds unnecessary complexity |
| Advanced Route Optimization | Can be evaluated after customer validation |
| Automated Marketing | Not essential to core workflows |
| Complex Inventory Management | Deferred until customer demand is established |
| Enterprise ERP Integrations | Not needed for initial customers |
| Advanced Analytics | Basic reporting is sufficient initially |

## 4. MVP Scope Rules

1. New features require a documented product justification.
2. Features outside the MVP cannot be added without reviewing their impact.
3. Core workflows take priority over visual enhancements.
4. Avoid introducing unnecessary dependencies.
5. Every completed feature must have appropriate tests.
6. Customer feedback will guide future scope changes.

## 5. Definition of MVP Success

The MVP must allow a business to:

- Register and create an organization.
- Log in securely.
- Manage customer records.
- Create and manage service jobs.
- Assign jobs to employees.
- Track job progress.
- View upcoming scheduled jobs.
- Access only its own organization's data.

The product must be deployed and usable by an initial pilot customer before considering the MVP complete.
